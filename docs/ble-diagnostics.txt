Hardware revision: 02FE low byte /10. Database code: 061F full U16.
Operating phase/subphase: 02E4 low/high byte. Operating detail/state:

P1..P5:0335..0339 U16; total is their U32 sum. Device resets/wraps are possible.

Implementation
- Diagnostics.h owns the bounded field map, request generation and decoding.
- BleFrame.h bounds response sizes and builds FC03/06/16 request envelopes.
  Consumer normal replies are complete notifications; MTU300 is requested.
  Identity reads require negotiated MTU>=51. No speculative fragment joining.
- Helper decrypts the complete accepted CBC ciphertext. Existing IV and header
  pairing is retained. Modbus function/count/CRC validate every response.
- User writes and alarm/control transactions precede diagnostic polling.
  Failed reads invalidate every diagnostic sharing the same register/count.
  A diagnostic pass continues after failure, without retrying a bad field forever.
- HA diagnostic discovery/state are retained; button commands are not retained.
  Each data entity has bridge and per-reading availability. A stale reading
  expires after ten minutes; cached values survive ordinary BLE sleep.
- AlarmReset.h implements a manually requested single write with fresh state
  and command reads. No state7 => no write. Resetbit already1 => no write.
  Power bit0==1 => Power command is on, no write or automatic switch-off.
  Only bit1 is set; other bits are retained. No automatic clearing/pulse/retry.
  Post-write verification reads state02E5 then alarm02E6. Cleared requires
  state!=7 AND alarmcode==0; otherwise the result is Alarm active at verification.
  This initial verification may precede delayed firmware handling; subsequent
  current state/alarm sensors remain authoritative. Another press never silently
  clears/re-pulses an already-set bit.

Additional commands are deliberately bounded to diagnosis refresh and the
explicitly requested manual alarm acknowledgment. No burner/auger actuator
tests, tuning writes, maintenance resets, firmware flashing or automatic start.
